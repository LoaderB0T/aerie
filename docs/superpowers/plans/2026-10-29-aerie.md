# Aerie Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A NeoForge 1.21.1 mod in which a multiblock shrine, plus optional relay totems, gives its owner creative flight in a fixed set of chunks around their base.

**Architecture:**
- **Pure Java rules.** These hold no Minecraft imports and are unit-tested with JUnit:
  - `Ownership`: click rules for owning and locking a Core
  - `Charge`: attunement progress and the anchor position
  - `Network`: which chunks are covered and which Core each relay is bound to
- **Thin Minecraft layer:**
  - block entities tick every second, validate their structures with Patchouli, and write into a per-dimension `SavedData` registry
  - a player-tick handler reads that registry and toggles a transient modifier on NeoForge's `CREATIVE_FLIGHT` attribute
  - a damage handler applies the combat cutoff

**Tech Stack:** Java 21, NeoForge 21.1.262 (ModDevGradle 2.0.148, Gradle 9.2.1 wrapper), Parchment 2024.11.17, Patchouli `1.21.1-93-NEOFORGE`, JUnit 5.

**Spec:** `docs/superpowers/specs/2026-10-29-aerie-design.md`

## Review Focus

1. **Negative chunk coordinates.** The base is at x/z < 0, and relays chain across the 0 line. Coverage must use Chebyshev distance correctly. Test: `Network` Task 3, `negativeCoordinatesChainAcrossOrigin`.
2. **A relay chain broken in the middle.** The relays downstream lose coverage but keep their binding. Rebuilding the middle relay restores everything, and another player's Core can't grab the orphans. Test: Task 3, `brokenChainKeepsBindingAndRestores`.
3. **The admin changes `chargeTimeSeconds` after a Core is charged.**
   - lowering it keeps the Core charged
   - raising it makes the Core charge the rest of the way
   - neither one resets progress

   Test: Task 2, `requiredTicksChangeKeepsProgress`.
4. **Two Cores owned by the same player with overlapping coverage.** Breaking one keeps flight in the other's chunks. Test: Task 3, `sameOwnerTwoCoresUnion`.
5. **The owner logs out, dies, or changes dimension while flying.** No flight should stay stuck. The modifier is transient, and checks always use the player's current level. Test: manual checklist item M9 in Task 8.

```java
public final class Ownership {
    public enum Result { CLAIMED, STATUS, LOCKED, UNLOCKED, DENIED }
    public @Nullable UUID owner();
    public boolean locked();
    public Result use(UUID clicker, boolean sneaking, boolean clickerIsOp);
    public void load(@Nullable UUID owner, boolean locked);
}
public final class Charge {
    public enum Event { NONE, RESET, COMPLETED }
    public int progress();
    public boolean charged(int requiredTicks);           // progress >= requiredTicks
    public float fraction(int requiredTicks);            // clamp(progress / required, 0, 1)
    public Event tick(int elapsedTicks, boolean complete, boolean powered, int requiredTicks);
    public boolean checkAnchor(long pos);                // true if it reset because pos moved
    public void reset();
    public long anchor();
    public void load(int progress, long anchor);         // anchor Long.MIN_VALUE = unset
}
```
`@Nullable` comes from `org.jetbrains.annotations`.

`Ownership.use` rules. CLAIMED tells the caller to reset the charge.

| sneaking | state | result |
|---|---|---|
| no | no owner | CLAIMED: owner = clicker, unlocked |
| no | clicker == owner | STATUS |
| no | locked, clicker ≠ owner | DENIED (an op too) |
| no | unlocked, clicker ≠ owner | CLAIMED: owner = clicker, unlocked |
| yes | no owner | STATUS |
| yes | clicker == owner, or clickerIsOp | toggle the lock → LOCKED / UNLOCKED |
| yes | otherwise | DENIED |

`Charge.tick` rules:
- If `!complete`: if progress > 0, reset and return RESET; otherwise return NONE.
- Otherwise, if `powered`: return NONE (paused, progress kept).
- Otherwise: `progress = min(progress + elapsed, max(progress, required))`. Return COMPLETED only on the tick where progress first reaches `required`, otherwise NONE.

`checkAnchor`: if the anchor is unset, store `pos` and return false. If it is different, store `pos`, `reset()` and return true.

**Interfaces:**
- Produces:
```java
public final class Network {
    public record CoreNode(long pos, long chunk, UUID owner, boolean active) {}   // owner may be null → covers nothing
    public record RelayNode(long pos, long chunk, boolean complete) {}
    public record Result(Map<UUID, Set<Long>> flightChunks, Set<Long> connectedRelays) {}
    public static long chunkKey(int x, int z);   // identical layout to ChunkPos.asLong: (x & 0xFFFFFFFFL) | ((z & 0xFFFFFFFFL) << 32)
    public static int chunkX(long key);
    public static int chunkZ(long key);
    /** Mutates bindings (relayPos → corePos). */
    public static Result recompute(Collection<CoreNode> cores, Collection<RelayNode> relays,
                                   Map<Long, Long> bindings, int maxDistance, boolean diagonal);
}
```

**Algorithm.** This is the part the signature does not decide:
1. Drop any binding whose relay is not in `relays`, or whose core is not in `cores`.
2. Go through the cores sorted by `pos` ascending, so the result is deterministic. For each core, run a BFS over chunks starting from `core.chunk`:
   - Candidates are relays that are `complete`, lie within Chebyshev distance `maxDistance` of `core.chunk`, and are either bound to this core or unbound.
   - A candidate's chunk is reached when it neighbours a chunk that is already reached. With `diagonal`, neighbouring means 8 directions, otherwise 4.
   - When a candidate is reached, bind it to this core if it was unbound, and add it to `connectedRelays`.
3. If the core is `active` and its `owner != null`, union the core's reached chunks into `flightChunks[owner]`.

An incomplete relay neither covers nor bridges, but it keeps its binding.

**`AerieNetworkData`:**
- Keeps maps of cores (pos → owner, name, active) and relays (pos → complete), plus `bindings`.
- Every `put*` / `remove*` call that changes anything sets `dirty = true` and calls `setDirty()`.
- `canFly`, `isConnected` and `boundOwnerName` call `Network.recompute(...)` lazily when `dirty`, using the `AerieConfig` distance and diagonal values, and cache the `Result`.
- Saves cores, relays and bindings to NBT as `long` positions, with UUIDs via `NbtUtils`.
- Uses the 1.21.1 `SavedData.Factory<>(AerieNetworkData::new, AerieNetworkData::load, null)`.

**`CoreBlockEntity`:**
- Holds `Ownership ownership`, `Charge charge`, `String ownerName`. It saves and loads all of them.
- `static serverTick(Level, BlockPos, BlockState, CoreBlockEntity)`, wired via `getTicker` on the server only. Every tick it does nothing unless `level.getGameTime() % 20 == 0`. On those ticks:
  - `charge.checkAnchor(pos.asLong())`
  - `complete = SHRINE.validate(level, pos) != null`
  - `powered = level.hasNeighborSignal(pos)`
  - `charge.tick(20, complete, powered, CHARGE_TIME_SECONDS * 20)`
- On `COMPLETED`: play `SoundEvents.BEACON_ACTIVATE` and send 40 `END_ROD` particles in a burst at the Core.
- Every 4 ticks, while it is complete, unpowered, owned and not yet charged: for each of the 4 Focus positions `pos.offset(±2, 1, ±2)`, send `PORTAL` particles along the line from the Focus to the Core. The count is `1 + (int)(fraction * 6)`.
- After the tick logic: `AerieNetworkData.get(level).putCore(pos, owner, ownerName, complete && charged && !powered)`. Call `setChanged()` when the state changed.
- No charge progress is made while unowned. Treat `owner == null` as incomplete for charging.

**`CoreBlock`:**
- `useWithoutItem` on the server:
  - `r = ownership.use(player.getUUID(), player.isShiftKeyDown(), player.hasPermissions(OP_PERMISSION_LEVEL))`
  - on `CLAIMED`: `charge.reset()` and `ownerName = player.getGameProfile().getName()`
  - send an action-bar message: `player.displayClientMessage(component, true)`
    - CLAIMED → `aerie.claimed`
    - LOCKED → `aerie.locked` with the owner name
    - UNLOCKED → `aerie.unlocked`
    - DENIED → `aerie.denied` with the owner name
    - STATUS → the status line
  - return `InteractionResult.SUCCESS`
- The status line is the first match:
  1. unowned
  2. incomplete
  3. disabled
  4. charging (whole percent)
  5. active, with `locked_suffix` if locked
- `onRemove` (when the block changes): `AerieNetworkData.get(level).removeCore(pos)`.

### Task 7: Flight handler

**Files:**
- Create: `src/main/java/com/loaderb0t/aerie/FlightHandler.java`
- Modify: `AerieMod.java`: `NeoForge.EVENT_BUS.register(FlightHandler.class)`, or use static `@SubscribeEvent` methods registered the same way

**Interfaces:**
- Consumes: `AerieNetworkData.canFly(UUID, long)` (Task 5), which is also used for the neighbouring-chunk checks in the border particles, and `AerieConfig` (Task 4)
- Produces: none

**Behaviour:**
- **State:** `static final ResourceLocation MODIFIER_ID = aerie:flight` and `static final Map<UUID, Long> lockoutUntil`, keyed by game time. Clear a player's entry on `PlayerEvent.PlayerLoggedOutEvent`.
- **`PlayerTickEvent.Post`**, server side, ServerPlayer only, every `CHECK_INTERVAL_TICKS` (`player.tickCount % interval == 0`):
  - Skip creative and spectator players.
  - `eligible = !lockedOut && data(player.serverLevel()).canFly(uuid, player.chunkPosition().toLong())`
  - `has = attr(CREATIVE_FLIGHT).hasModifier(MODIFIER_ID)`
  - If `eligible && !has`: `addTransientModifier(new AttributeModifier(MODIFIER_ID, 1.0, ADD_VALUE))`.
  - If `!eligible && has`: remember `wasFlying = player.getAbilities().flying`, then remove the modifier and call `stopFlyingIfNoOtherSource(player)`. Then, if `wasFlying`, `!player.mayFly()` and `LEAVE_GRACE_SECONDS > 0`, apply `new MobEffectInstance(MobEffects.SLOW_FALLING, LEAVE_GRACE_SECONDS * 20)`.
  - **Border particles**, if `BORDER_PARTICLES`, `has` and flying: for each of the 4 sides, check whether the player is within 4 blocks of that side's edge of their current chunk and the neighbouring chunk on that side is not `canFly`. If so, send 6 `END_ROD` particles spread along that edge plane within ±4 blocks horizontally and ±3 vertically of the player. Send them only to that player: `serverLevel.sendParticles(player, END_ROD, true, x, y, z, 1, 0, 0, 0, 0)`.
- **`LivingDamageEvent.Post`**, server side. Let `src = event.getSource()`, `target = event.getEntity()`, and `attackerEnemy = src.getEntity() instanceof Enemy || src.getDirectEntity() instanceof Enemy`.
  - If `target instanceof ServerPlayer p && attackerEnemy`, then `cutOff(p)`.
  - Else if `target instanceof Enemy && src.getEntity() instanceof ServerPlayer p`, then `cutOff(p)`.
- **`cutOff(p)`:**
  - set `lockoutUntil[p] = gameTime + COMBAT_LOCKOUT_SECONDS * 20`
  - if the modifier is present, remove it and call `stopFlyingIfNoOtherSource(p)`, with no grace
  - apply this even when the player wasn't flying
- **`static void stopFlyingIfNoOtherSource(ServerPlayer p)`:** if `p.getAbilities().flying && !p.mayFly()`, set `abilities.flying = false` and call `p.onUpdateAbilities()`.
  - `mayFly()` is NeoForge's `IPlayerExtension#mayFly`: it is `abilities.mayfly || CREATIVE_FLIGHT > 0`. So a player who still has flight from creative mode, Ars Nouveau or anything else keeps flying.
  - Aerie never writes `abilities.mayfly`, and touches no ability anywhere else.
